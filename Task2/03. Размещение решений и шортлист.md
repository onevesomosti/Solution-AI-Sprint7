## Размещение решений

| Инициатива | Пилот | Целевой продакшен | Обоснование |
| --- | --- | --- | --- |
| №1 Подозрительные операции | On-prem / внутренний облачный контур | On-prem или self-hosting в облачном контуре банка | Исходные операции содержат банковскую тайну,возможность передачи наружу не подтверждена |
| №10 Поддельные документы | Внутренний контур | On-prem / self-hosting в облаке | Кредитные документы могут содержать банковскую тайну и ПДн |
| №18 Извлечение показателей | Public API допустим только для синтетических/обезличенных данных после согласования | Выделенный контур либо self-hosting | Позволяет быстро проверить гипотезу, не отправляя реальные чувствительные документы в публичный API |

## Шортлист моделей и процедура выбора

| Инициатива | Кандидаты после hard constraints |
| --- | --- |
| №1 | Модели поиска аномалий / ранжирования, доступные для self-hosting |
| №10 | CV/document-модели обнаружения аномалий и классификации, доступные для допустимого контура |
| №18 | Мультимодальная модель, OCR + специализированная extraction/text-модель |

### Приёмочный набор

#### №1
Сценарии:
- крупные операции
- дробление платежей
- необычные контрагенты
- необычное назначение платежа
- операции, не выбранные существующими правилами
- разные клиентские сегменты и суммы

### №10
Сценарии:
- подлинный документ
- подтверждённая подделка
- редактированный документ
- скан низкого качества
- фотография с телефона
- разные типы кредитных документов

### №18
Сценарии:
- Excel
- цифровой PDF
- PDF-скан
- фотография
- отсутствующее поле
- нестандартное расположение поля
- плохое качество изображения
- разные формы бухгалтерских документов

### Критерии выбора

Модель проходит дальше, если:
- соблюдает выходной контракт
- не проваливается на критическом сценарии
- укладывается в допустимый контур размещения
- соответствует ограничениям по задержке и стоимости
- её ошибки контролируются правилами или ручной проверкой

Численные пороги качества должны быть зафиксированы после измерения baseline и согласования цены ошибок с бизнесом. Провал критического сценария означает, что кандидат либо исключается, либо сценарий переводится на отдельную модель/детерминированный алгоритм/ручную проверку.

Решение пересматривается при изменении версии модели, цены, SLA, законодательства, допустимого контура либо появлении кандидата, который выполняет выходной контракт при меньшей стоимости.
