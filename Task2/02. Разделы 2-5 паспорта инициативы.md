# Паспорт инициатив

## Паспорт инициативы №1. Выявление подозрительных операций

### 2. Постановка

| Поле | Решение |
| --- | --- |
| Бизнес-цель | Повысить результативность работы финмониторинга |
| Объект решения | Операция по счёту клиента |
| Входные данные | Сумма, назначение платежа, контрагент, ОКВЭД, дата, канал, история операций и доступные внешние сигналы |
| Операция | Поиск аномалий / скоринг подозрительности и ранжирование операций.|
| Результат модели | Оценка подозрительности операции |
| Результат для бизнеса | Приоритизированная очередь операций для проверки финмониторингом |
| Дальнейшее действие | Сотрудник проверяет наиболее приоритетные операции, модель не принимает окончательного решения |
| Источник правильного ответа | Исход расследования и формально подтверждённые случаи |
| Роль правил | Пороговые проверки, известные признаки и внешние сигналы остаются детерминированным контуром |
| Роль человека | Финальное решение и расследование остаются за сотрудником банка |

### 3. Качество

| Поле | Решение |
| --- | --- |
| Бизнес-действие | Изменить порядок ручной проверки операций |
| Положительный класс | Операция, которую эксперт считает требующей дальнейшей проверки |
| Основная метрика | Precision среди первых N операций в очереди. Дополнительно — recall и PR-AUC после накопления надёжной разметки |
| Baseline | Текущая очередь, сформированная пороговыми правилами и внешними сигналами |
| Выборка для проверки | Экспертно размеченная вероятностная контрольная выборка + размеченная рабочая очередь |
| Рабочая точка | Первые N операций, N определяется пропускной способностью финмониторинга |
| Guardrail | Объём ручной очереди не должен превышать текущую способность обработки (около 10 тысяч операций в месяц) |
| Критерий успеха | При той же ёмкости ручной проверки новая очередь должна давать лучший результат, чем текущий baseline |

### 4. Данные

| Поле | Оценка |
| --- | --- |
| Источник и владелец | История операций RetailBank, владелец должен быть подтверждён банком |
| Источник правильного ответа | Экспертная разметка финмониторинга + исход расследования + вероятностная контрольная выборка |
| Качество | История операций есть за несколько лет, назначение платежа - свободный текст |
| Объём | 20–25 миллионов операций в месяц, но подтверждённых схем - единицы |
| Разметка | Требуется гайдлайн и разметка экспертами с оценкой согласованности |
| Смещение отбора | Высокое: исторически проверялись операции, уже выбранные правилами и внешними сигналами |
| Репрезентативность | Текущая размеченная выборка не представляет весь поток операций |
| Право использования | Операционные данные относятся к банковской тайне. Допустимость конкретного потока и контура должны подтвердить комплаенс/DPO/юристы |
| Разрыв | Нет достаточного несмещённого источника правильного ответа |

Вердикт: разрыв с планом закрытия.

#### План закрытия разрыва
1. Создать гайдлайн экспертной разметки
2. Размечать результаты приоритетной очереди сотрудниками финмониторинга
3. Параллельно постоянно формировать вероятностную контрольную выборку из общего потока
4. Проверять согласованность между разметчиками
5. Результаты расследований использовать как дополнительный сигнал, но не считать эскалацию подтверждённой схемой

### 5. Эксперимент

| Поле | Решение |
| --- | --- |
| Проблема | Текущая очередь не позволяет обработать весь поток отмеченных операций |
| Baseline | Приоритизация по существующим правилам |
| Гипотеза | Ранжирование позволит увеличить долю действительно значимых случаев среди первых N операций |
| Эксперимент | Тестовый прогон: новая система формирует очередь параллельно текущему процессу, не принимая решений |
| Выборка | Рабочая очередь + вероятностная контрольная выборка |
| Метрика | Precision, после накопления разметки — recall и PR-AUC |
| Guardrail | Не увеличивать объём ручной проверки сверх текущей ёмкости |
| Решение | Продолжать, если ранжирование превосходит baseline, иначе пересмотреть признаки, постановку или остановить эксперимент |

## 2. Паспорт инициативы №10. Выявление поддельных или изменённых документов

### 2. Постановка

| Поле | Решение |
| --- | --- |
| Бизнес-цель | Снизить риск принятия кредитных решений на основе поддельной или изменённой отчётности |
| Объект решения | Документ из кредитной заявки |
| Входные данные | PDF-сканы, фотографии, бухгалтерская отчётность и справки |
| Операция | Классификация документа, выявление признаков подделки |
| Результат модели | Оценка вероятности или признак подозрительности документа |
| Результат для бизнеса | Документы, требующие дополнительной проверки |
| Дальнейшее действие | Подозрительный документ передаётся сотруднику на проверку |
| Источник правильного ответа | Подтверждённые экспертами подлинные и поддельные/отредактированные документы |
| Роль правил | Проверка формата, реквизитов и других детерминированных признаков |
| Роль человека | Подтверждение подделки и решение по кредитной заявке |

### 3. Качество

| Поле | Решение |
| --- | --- |
| Бизнес-действие | Направить подозрительный документ на проверку |
| Положительный класс | Поддельный / изменённый документ |
| Метрики | Recall по подделкам + precision |
| Baseline | Текущий ручной процесс проверки |
| Выборка | Подтверждённые подлинные и поддельные документы разных типов и форматов |
| Рабочая точка | Порог подозрительности, при котором документ направляется сотруднику |
| Guardrail | Нагрузка дополнительной проверки не должна превышать согласованную бизнесом ёмкость |

### 4. Данные

| Поле | Оценка |
| --- | --- |
| Источник и владелец | Кредитные заявки, владелец требует уточнения |
| Источник правильного ответа | Экспертно подтверждённые случаи |
| Качество | Форматы разнородны: PDF, сканы, фотографии |
| Объём важного класса | Не указан |
| Разметка | Готовая разметка не подтверждена |
| Смещение отбора | Возможное: проверенные документы могут отличаться от общего потока |
| Репрезентативность | Требуется покрыть разные документы, форматы и качество изображений |
| Право использования | Возможны банковская тайна и персональные данные. Допустимость использования и размещения подтверждают юристы/DPO |
| Разрыв | Не подтверждено наличие достаточного количества размеченных подделок |

Вердикт: разрыв с планом закрытия.

#### План закрытия разрыва
1. Инвентаризировать подтверждённые случаи
2. Определить объём важного класса
3. Разработать правила разметки
4. Собрать репрезентативный датасет
5. Проверить право использования

### 5. Эксперимент

Собрать отложенный набор из подтверждённых подлинных и поддельных документов. Сравнить несколько кандидатов по recall и precision отдельно для разных типов документов и качества изображения.

Провал на конкретном типе документа означает не усреднение результата, а отдельный анализ этого сценария. 

## 3. Паспорт инициативы №18. Извлечение финансовых показателей

### 2. Постановка

| Поле | Решение |
| --- | --- |
| Бизнес-цель | Сократить ручной разбор кредитного пакета, который сейчас занимает в среднем полтора часа |
| Объект решения | Документ кредитной заявки |
| Входные данные | Выписки, бухгалтерская отчётность, договоры и справки в Excel, PDF, выгрузках и фотографиях |
| Операция | Извлечение структуры из документа |
| Результат модели | Набор финансовых показателей и их значений |
| Результат для бизнеса | Структурированные показатели для дальнейшего процесса андеррайтинга |
| Дальнейшее действие | Валидация показателей и использование сотрудником при разборе кредитной заявки |
| Источник правильного ответа | Проверенные сотрудниками значения показателей в документах |
| Роль правил | OCR/парсинг, проверка типов, арифметических соотношений и других детерминированных инвариантов |
| Роль человека | Проверка спорных или не прошедших валидацию значений |

### 3. Качество

| Поле | Решение |
| --- | --- |
| Бизнес-действие | Использовать извлечённые показатели в процессе андеррайтинга |
| Основные метрики | Доля корректно извлечённых полей, доля документов без ручного исправления |
| Baseline | Полностью ручной разбор, около 1,5 часа на пакет |
| Выборка | Реальные документы разных форматов и качества |
| Guardrail | Отсутствующее значение нельзя заменять выдуманным |
| Рабочая точка | Низкая уверенность / ошибка валидации требует ручной проверки |

Для задачи по извлечению важен именно выходной контракт. Готовая модель должна проверяться на собственных документах, а не выбираться по публичному рейтингу.

### 4. Данные

| Поле | Оценка |
| --- | --- |
| Источник и владелец | Кредитные пакеты, владелец требует подтверждения |
| Источник правильного ответа | Проверенные сотрудниками финансовые показатели |
| Качество | Высокая вариативность форматов и качества документов |
| Объём важного класса | Не указан |
| Разметка | Неизвестно, сохраняются ли результаты ручного разбора в форме, связанной с исходным документом |
| Смещение отбора | Требуется проверить |
| Репрезентативность | Нужны Excel, PDF, сканы, выгрузки и фотографии разных типов |
| Право использования | Требует проверки из-за банковской тайны и персональных данных |
| Разрыв | Не подтверждён готовый связанный набор 'документ + проверенные поля' |

Вердикт: можно начинать пилот если пилот проводится на согласованном обезличенном/допустимом наборе документов с ручной эталонной разметкой. Для полноценного обучения собственных моделей готовность данных пока не подтверждена.

### 5. Эксперимент

Сравнить два сквозных пути:
1. документ → мультимодальная модель → структурированные поля
2. локальный OCR/парсер → текст → модель → структурированные поля

Сравнение проводить по качеству извлечения, доле выдуманных значений, задержке и стоимости.
