# Инициативы для дальнейшей проработки

Для дальнейшей проработки выбраны три кандидата:
1. №1 - Выявление подозрительных операций (флагман)
2. №10 — Выявление поддельных и отредактированных документов
3. №18 — Извлечение финансовых показателей из неструктурированных документов

## Инициатива №1 - Выявление подозрительных операций

| Поле | Постановка |
| --- | --- |
| Бизнес-цель | Повысить результативность работы финмониторинга: из 35 тысяч помеченных операций при ограниченной мощности проверки приоритизировать наиболее подозрительные |
| Объект решения | Операция по счёту клиента |
| Входные данные | Сумма, назначение платежа, контрагент, ОКВЭД, дата, канал, история операций и доступные внешние сигналы |
| Операция | Поиск аномалий / скоринг подозрительности и ранжирование операций.|
| Модальность | Табличные данные + назначение платежа |
| Результат модели | Оценка подозрительности операции |
| Результат для бизнеса | Приоритизированная очередь операций для проверки финмониторингом |
| Дальнейшее действие | Сотрудник проверяет наиболее приоритетные операции, модель не принимает окончательного решения |
| Источник правильного ответа | Исход расследования и формально подтверждённые случаи |
| Роль правил | Пороговые проверки, известные признаки и внешние сигналы остаются детерминированным контуром |
| Роль человека | Финальное решение и расследование остаются за сотрудником банка |
| Открытые вопросы | Как сформировать пригодный источник сигнала при отсутствии готовой разметки схема / не схема ? |

Главное ограничение данных: около 400 операций в месяц эскалируются на расследование, но эскалация не означает подтверждённую схему, а формально подтверждённых случаев — единицы. Кроме того, историческая выборка смещена, поскольку сотрудники проверяли операции, уже отобранные правилами и внешними сигналами. Непроверенную операцию нельзя считать чистой.

## Инициатива №10 - Выявление поддельных документов

| Поле | Постановка |
| --- | --- |
| Бизнес-цель | Снизить риск принятия кредитных решений на основе поддельной или изменённой отчётности |
| Объект решения | Документ из кредитной заявки |
| Входные данные | PDF-сканы, фотографии, бухгалтерская отчётность и справки |
| Операция | Классификация документа, выявление признаков подделки |
| Модальность | Документ / изображение |
| Результат модели | Оценка вероятности или признак подозрительности документа |
| Результат для бизнеса | Документы, требующие дополнительной проверки |
| Дальнейшее действие | Подозрительный документ передаётся сотруднику на проверку |
| Источник правильного ответа | Подтверждённые экспертами подлинные и поддельные/отредактированные документы |
| Роль правил | Проверка формата, реквизитов и других детерминированных признаков |
| Роль человека | Подтверждение подделки и решение по кредитной заявке |
| Открытый вопрос | Есть ли история документов с надёжно подтверждённым фактом подделки и достаточно ли таких примеров? |

Ручная разметка объектов является отдельной статьёй стоимости. В описании кейса наличие такой готовой разметки не указано, поэтому это ключевой gap, который необходимо проверить до обучения модели.

## Инициатива №18 - Извлечение финансовых показателей

| Поле | Постановка |
| --- | --- |
| Бизнес-цель | Сократить ручной разбор кредитного пакета, который сейчас занимает в среднем полтора часа |
| Объект решения | Документ кредитной заявки |
| Входные данные | Выписки, бухгалтерская отчётность, договоры и справки в Excel, PDF, выгрузках и фотографиях |
| Операция | Извлечение структуры из документа |
| Модальность| Текст + документ/скан |
| Результат модели | Набор финансовых показателей и их значений |
| Результат для бизнеса | Структурированные показатели для дальнейшего процесса андеррайтинга |
| Дальнейшее действие | Валидация показателей и использование сотрудником при разборе кредитной заявки |
| Источник правильного ответа | Проверенные сотрудниками значения показателей в документах |
| Роль правил | OCR/парсинг, проверка типов, арифметических соотношений и других детерминированных инвариантов |
| Роль человека | Проверка спорных или не прошедших валидацию значений |
| Открытый вопрос | Сохраняются ли сейчас результаты ручного разбора андеррайтерами так, чтобы их можно было сопоставить с исходным документом? |
