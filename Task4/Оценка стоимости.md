## Денежный эффект

### Что можно посчитать

Из кейса напрямую известен ФОТ финмониторинга — 45 млн р/год

Если приоритизация и интерфейс уменьшат трудозатраты, эквивалентный эффект составит:
| Снижение трудозатрат | Эквивалент эффекта/год |
| -------------------- | ---------------------: |
| 5 % | 2,25 млн р |
| 10 % | 4,50 млн р |
| 15 % | 6,75 млн р |
| 20 % | 9,00 млн р |

Снижение трудозатрат становится денежной экономией только если банк действительно уменьшает расходы либо использует высвободившуюся ёмкость вместо расширения штата. При TCO 11,58 млн р за два года точка безубыточности только по этому эффекту соответствует примерно 12,9 % ФОТ за два года.

### Что пока нельзя перевести в деньги

Пока не известна стоимость:
- дополнительного подтверждённого подозрения
- предотвращённой схемной операции
- одной ошибочной приостановки
- одной жалобы
- ухода клиента
- одного предписания регулятора

Поэтому нельзя корректно посчитать денежный эффект от роста доли подтверждённых подозрений, более раннего выявления, сокращения 450 снимаемых приостановок или 120 жалоб в месяц. Поэтому на текущих данных нельзя обоснованно утверждать положительный ROI. Сначала необходимо измерить эффект на пилоте.

## План пилота

Пилот проверяет допущения, способные изменить экономическое решение. Модель формирует приоритет, но не блокирует операции автоматически.

| Неопределённость | Как проверяем | Критерий успеха |
| --- | --- | --- |
| Растёт ли результативность первых N проверок | Сравнить приоритизированную очередь с текущим baseline | Результативность выше baseline |
| Сокращается ли время проверки | Замерить время до/после | Снижение достаточно для экономического эффекта |
| Не возникает ли новый selection bias | Сохранять постоянную контрольную выборку | Контрольная выборка остаётся независимой от ML-очереди |
| Укладывается ли стоимость в TCO | Измерить реальную стоимость целевого потока | Не выше плановой стоимости единицы |
| Работает ли fallback | Искусственно проверить недоступность модели/признаков | Текущие правила продолжают работать |
| Достаточен ли источник сигнала | Разметка очереди + контрольной выборки | Возможно сравнение ML и baseline |

## Guardrails

Показатели, которые не должны ухудшиться, даже если результативность модели растёт:

| Guardrail | Требование |
| --- | --- |
| Время проверки операции | Не растёт относительно baseline |
| Размер/возраст очереди | Не ухудшается |
| Лишние приостановки | Не растут относительно ~600/мес |
| Снятые после проверки приостановки | Не растут относительно ~450/мес |
| Жалобы клиентов | Не растут относительно ~120/мес |
| Пропуск крупных рискованных операций | Не ухудшается относительно текущего процесса |
| Доступность процесса | При отказе ML сохраняется текущий путь |

## Критерии остановки

Пилот прекращается, если:
- результативность проверок после устранения технических проблем не выше baseline
- ручная нагрузка не снижается или увеличивается настолько, что экономический эффект отсутствует
- стоимость обработки единицы выше измеренного эффекта на единицу
- контрольная выборка показывает деградацию на сегментах, которую не видно в ML-очереди
- растёт число необоснованных приостановок или жалоб
- невозможно получить правовое основание для обработки данных в выбранном контуре

## Итоговый ADR

```
## ADR-001. Приоритизация подозрительных операций. v1.0

### Решение

**Запустить ограниченный пилот сервиса приоритизации ручной проверки.**

Модель ранжирует операции, но не выносит вердикт «схема / не схема» и не инициирует действия в отношении клиента без сотрудника финмониторинга.

### История решения

* **v0.1** — отказ от классификатора «схема / не схема»: подтверждённых случаев недостаточно, историческая выборка смещена.
* **v0.2** — выбран сервис ранжирования операций для ручной проверки, разметка накапливается из ML-очереди и независимой контрольной выборки.
* **дополнение** — модель выделена в отдельное вероятностное звено, а калибровка, правила, валидация и fallback детерминированы.
* **v1.0** — запуск ограниченного пилота для проверки экономического эффекта.

### Экономика
- TCO год 1 — ≈7,94 млн р.
- TCO год 2 — ≈3,64 млн р.
- TCO за два года — ≈11,58 млн р.
- Стоимость оценки операции — ≈18,9 р в первый год, ≈8,7 р во второй.

На текущих данных положительный ROI не доказан, поскольку стоимость предотвращённых нарушений, ложных приостановок, жалоб и регуляторных последствий не известна.

### Критичные допущения
1. Приоритизация увеличивает результативность проверяемой выборки
2. Сервис уменьшает трудозатраты либо позволяет обрабатывать больше операций тем же штатом
3. Результат сохраняется на независимой контрольной выборке

Все три допущения проверяются пилотом.

### Критерии остановки
- результативность не выше baseline
- экономии/роста полезной пропускной способности нет
- стоимость единицы выше эффекта
- ухудшаются клиентские guardrails
- отсутствует правовое основание для выбранного контура

### Пересмотр

Решение пересматривается при:
- существенном изменении объёма операций
- изменении стоимости инфраструктуры
- появлении достаточной подтверждённой разметки
- смене модели или поставщика
- изменении требований законодательства или комплаенса

### Рекомендация бизнесу

Не переходить сразу к production-внедрению. Провести ограниченный пилот приоритизации.

Описание кейса подтверждает проблему — из ~35 тыс. помеченных операций банк способен проверить только ~10 тыс, при ФОТ финмониторинга около 45 млн р/год. Однако данных пока недостаточно, чтобы доказать денежный эффект новой приоритизации.

Поэтому пилот должен подтвердить прежде всего рост результативности проверок, изменение трудозатрат и отсутствие ухудшения клиентских показателей. Только после этого эффект можно сопоставить с TCO и принять решение о промышленном запуске.
